## Goals / Non-Goals

**Goals:** 将调用方提供的标准声明变为可审查、明确范围的设备执行；保留每个实际阶段的事实、失败和恢复边界。

**Non-Goals:** 编译业务策略，解释调用方生成器元数据，选择或合并部署基线，安排主机/交换机迁移，决定业务允许/拒绝路径，自动执行现场验收。通用依赖排序不决定业务迁移顺序，调用方可组织多次独立执行。

## Decisions

### 1. 复用现有入口，新增固定操作

继续使用 `iaas run --component opnsense --operation ... --scope <单个 inventory host>`。新增名称为 read、plan、apply、verify；旧 check/generate/diagnose 不改名、不变成写操作。

| 操作 | 输入 | 设备效果 |
| --- | --- | --- |
| read | inventory、request | 只读选定配置及必要关联信息 |
| plan | 标准资源 inputs、inventory、request；恢复模式改为 recovery 文件 | 在线读取差异，生成新的私有 candidate；不保存或激活 |
| apply | inventory、candidate、已审查 candidate 摘要及本次执行前置结论 | 写前准入后执行候选指定集合和阶段 |
| verify | inventory、candidate | 独立读取保存态及受支持活动状态；不刷新、激活或清理 state |

复用 `environment.yml` 的 `inputs / files / options`，不新增本站专用顶层字段。`files.inventory`、`files.request`、`files.candidate`、`files.recovery` 是按操作选择的通用文件别名；request 使用版本化固定字段表达资源选择、显式接管对象及激活恢复请求，不接受脚本、任意 endpoint、业务角色或工作流步骤。apply/verify 不重新装载当前标准资源 inputs 或运行生成器。plan 的恢复模式与普通 desired inputs 互斥。

候选由单个自包含 JSON 文件保存完整已解析标准声明、目标、选中身份、执行阶段、规范化写前观测、必要引用、提供者/镜像 digest/架构和来源元数据。只保存配置和安全连接标识，不保存凭据。配套摘要记录一个候选文件 SHA-256；apply 通过 `options.candidate_sha256` 接受审查时的摘要，校验后从同一份已加载内容执行。候选修改需重新 plan/review；不建逐对象 hash、签名链或跨机器信任系统。

目标绑定 inventory 主机名及实际 API endpoint/TLS 配置；仅名称相同但地址变更也拒绝。凭据仍在执行时由调用方注入。来源记录实际运行时、输入来源和可取得的 Git HEAD/dirty，无法取得或仓库外输入明确标记，不把 HEAD 当字节证明。

采用现有 file aliases 而不是平行 CLI 或 Docker 包装器；单文件候选使 local/DinD 可沿用显式文件传输，避免借用 PVE `--plan` 的二进制计划与 companion/state 合同。

### 2. 范围、身份与读取完整性

首版仅 aliases、vips（IP Alias）、gateways（PBR）、filter-rules、dnat、one-to-one-nat、interface-groups。各类别的稳定身份直接采用现有 schema/模块匹配合同；不得按 sequence、相似地址或描述文本猜测其他对象。read 按请求的类别或稳定身份读取现场，不要求候选；plan 从标准输入选择，apply/verify 使用候选固定集合。声明选择中的类别表示该类别全部输入声明，对象选择必须精确匹配输入/候选身份；现场不存在的合法 present 仍可新增。缺失选择、非法/重复身份拒绝；显式空执行集合是 no-op，不变成全量清理。

选中且现场不存在的 present 是新增；现场相同稳定身份的已管对象可更新；首次接管同名既有对象须由调用方在请求中明确选择并接受其现场差异。多个现场匹配拒绝。不得自动接管 legacy/自动生成过滤对象。DNAT 关联过滤仍归 DNAT，不单独声明或计为另一个受管对象。

读取适配复用固定 Collection 的列举/查询能力及已有受限诊断客户端；按资源做规范化，不创建可配置任意 endpoint 的客户端。分页、超时和响应大小均有界；列举截断、缺少必要字段、重复匹配或请求失败返回 unknown/incomplete，而不是不存在/no-change。必要的反向引用读取可涉及未选中类别，但只读取相关范围，不能加入其 desired inputs 或写集合；调用方可看到读取覆盖范围。

差异只比较受支持配置语义及原生默认值，不比较计数器/时间戳；顺序、地址族、端口、gateway 等语义保留。URL/DNS Alias 的动态成员变化与声明漂移分开；有表项不代表周期刷新成功。无法无损表达的原生状态不得归一化成普通受管对象。

### 3. 完整候选与执行集合分离

先校验完整候选的标准声明和本地已知引用；这不声称完整候选已部署。在线构建本次有效状态：选中对象采用候选期望值，未选中对象采用必要的现场观测，包括涉及删除、类型变化或引用切换的反向引用。

仅在本次集合内按支持的依赖排序：满足新引用、切换引用、退役旧对象。受支持关系包括 Alias 成员、规则/NAT 的 Alias 引用、filter 的 PBR gateway 引用和 filter/NAT 的接口组引用；物理接口存在性可读校验但不由工作流创建。每个阶段必须满足当时的保存态和所需活动态依赖。不能安全排序、存在环或需要未选中写入时，在首个写入前拒绝，提示缺少的选择或要求调用方分阶段。

复用资源 playbook 和批次任务，允许将同一类别的创建与退役分成独立阶段。每阶段沿用固定资源 target 的一次激活，不默认把所有资源只在结尾 reload；也不声称多个 reload 是事务。需要细分时提取可复用任务，直接 Ansible 的本地校验、加载后复验和 no-op/check-mode 行为保持一致。

### 4. 漂移与共享激活准入

plan 保存受影响对象及必要引用的相关观测。apply 在首个写入前重读并对比，包含新增目标应仍不存在、已有对象身份和必要依赖；相关漂移/unknown 则输出差异并停止，不能自动重算候选或扩大授权。

共享 filter reload 的影响大于 CRUD 集合。能观测到未经本次授权覆盖的待激活修改时停止；提供者不能自动判断时输出 unknown，并要求调用方提供绑定目标、候选和本次执行的显式“已检查无额外待激活修改”结论。它只作为调用方承担的前置条件记录，不能覆盖检测到的冲突，也不能代替配置/活动验证。没有该结论时在首个写入前拒绝；复用旧执行结论不成立。

调用方在整个执行期串行化目标写入，包括 UI 修改；每个共享激活阶段重评可观测的冲突和阶段依赖，发现外部变化即停。调用方确认不提供事务隔离，也不要求读取全设备逐对象快照。维持现有备份、savepoint 和管理通路要求，但不把整设备备份回滚实现进本工作流。

### 5. 保存、激活与验证

阶段结果分别记录 attempted/save/activation/configuration/active-check，不以一个 changed 或 HTTP ok 推导全部成功。CRUD 失败停止后续写入和激活；激活失败或无法确认时停止后续依赖阶段。超时/中断仅尝试有界回读，无法连接则保留 unknown，不整批重试。

固定提供者/API 的激活成功语义须先核对。例如 Groups 的 `reconfigure` 返回 ok 可能只证明已调用 reload；若没有可信完成结果，应由受支持的活动核对确认，否则 activation=unconfirmed。不能把再次读到保存态当作活动证明。

每类资源声明其配置核对和活动检查能力。配置回读比较本次选中对象，包含 absent；PF、路由或 Alias 表按实际支持标记 verified/failed/unsupported/unconfirmed，并写明覆盖范围。必要活动条件未确认时不得继续依赖阶段或报告完全成功。无设备活动检查能力本身不捏造失败或通过，独立标出未验证项。

read/plan 必需信息不完整、apply 必需阶段失败/未知、verify 必需核对不符均返回非零；只读结果仍保留可确认部分。所有必需阶段成功但存在不支持的附加活动检查时可报告 completed_with_unverified，不能标为 fully_verified。业务测试不由 iaas 发起或判定。

普通 no-op 不 reload；需要恢复此前已保存但未激活配置时，必须在新审查候选中显式选择 activation_recovery，仍执行漂移/共享激活准入。直接 Ansible 的 strict boolean force-reload 保留，不变成统一入口的隐式重试。

### 6. 有界恢复及结果交接

在首个写入前，将每个可能写入对象的实际旧配置、原本不存在标记及恢复可表达性保存到私有 recovery 文件；候选声明不能代替写前值。同一自包含 recovery 文件绑定本次执行，随执行记录已尝试阶段及可确认后态；后态未取得、更新或采集失败时按 unknown 处理，不依赖原任务目录中的未声明伴随文件。不能完整重建的模式/原生字段标 manual_required，并在计划中说明，不能输出一个看似可自动恢复的有损候选。

恢复沿用 plan/apply：plan 选择某次执行的 recovery，先回读当前配置，对照已确认执行后状态并生成新的反向候选。更新/删除对象恢复旧受管配置，新增对象生成显式 absent。现场有后续修改或原执行结果未知时，先核清并审查当前差异，不自动执行逆操作；需要人工恢复的对象拒绝自动恢复选择。只恢复受影响对象，不回退全设备或清理 PF state。

通用结果记录目标、候选摘要、runtime、资源身份、各阶段结果、已知前后差异、未验证项、恢复材料位置和采集完整性。私有 API 响应、配置、工具输出使用现有 0700 目录/0600 文件与受保护捕获；输出无法准备时不写设备，回收失败保留任务材料。

iaas 不消费或改写调用方 `review.yml`、activation 目录、部署指针和生成器所有权，不返回“该业务策略已部署”结论。调用方自行利用通用结果维护部分执行记录与一致基线；这不是 iaas 的状态库或 `--previous` 服务。

## Risks / Trade-offs

- [资源读取或激活可观测性不完整] → 在实现初期用固定源码和代表性响应验证；未支持检查显式输出，必需能力不足则在写前拒绝对应操作，不虚构设备证据。
- [并发窗口与共享 reload] → 调用方串行化、写前及阶段相关检查；保留无法自动检测的边界，不建设锁服务或全设备证据系统。
- [资源保存后失去管理通路] → 保留 partial/unknown 和恢复材料，调用方负责带外通路；不承诺自动回滚。
- [通用实现被站点需求拖宽] → 仅消费标准资源、仅合成示例，IO-01–IO-07 无实现任务进入本 change。

## Migration Plan

按任务顺序实现读取/候选，再接入受控执行/恢复与现有 launcher。通用手册替换“只有直接 playbook、一次只能一种资源”的旧限制，同时保留旧入口说明、资源字段和显式设备授权。发布及调用方版本切换不由本次设计操作触发；未发布前旧版本仍只具有原操作。

软件验证使用两种合成目录布局、按资源差异分组的代表性用例和受影响 local/DinD 路径，不做全版本/全对象矩阵。真实设备变更、业务验收与调用方基线迁移另行授权，由调用方接入阶段完成；延后不影响本 change 的软件合同验收，但不得宣称现场通过。
