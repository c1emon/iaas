## Context

动机见 proposal.md。当前 `Reader._read_one` 保留不可表达对象的身份和引用，但恢复属性主要由 `configuration` 是否为空决定；资源级 `read_only=true` 表示读取操作不写设备。`runtime.read_selected` 执行读取选择，计划与执行直接使用 Reader 的观察。Filter 的配置来源为 `firewall/filter/get`，不能据此宣称完整 PF 活动规则覆盖。

分类必须基于已支持设备／固定 Collection 的原生契约。交接中的 Alias、VPN 组是待核实的代表性系统项；两个不可表达 Gateway 的来源仍未知。上游主分支机制不直接成为当前设备的已验证字段契约。

## Goals / Non-Goals

- 用现有资源适配边界实现最小分类和可预测的读取视图，保护计划与恢复的准入。
- 完整指受请求选择、固定端点、分页与预算约束的完整观察；不做全设备快照。
- 沿用现有脱敏和私有产物机制，不保存原始敏感响应作为分类依据。
- 本轮只新增 change 文档，不改源码、主 specs、运行版本或设备。

## Decisions

### 1. 来源、管理能力与可表达性分别记录

在对象观察中增加 `classification`，最小字段如下；不建立新的资源框架。

| 字段 | 语义 |
| --- | --- |
| `origin` | `user_config`、`system_builtin`、`derived`、`unknown` |
| `management` | `independent`、`via_source`、`read_only`、`unknown` |
| `basis` | 受控的规则标识、原生字段名、适用版本依据；不包含原始响应或任意异常值 |
| `source` | 有证据时记录来源资源／配置位置；无可靠关联则不猜测 |

配置可表达性继续由 `configuration` 和转换原因表达，不为同一事实维护第二套可漂移状态。配置、动态成员和运行状态在相关观察中分别标识数据性质；不把 URL Alias 的动态成员等同于不可管理对象。

`user_config` 表示独立持久化配置类别，不声称实际由人手工创建，也不代表 IaaS 已获管理授权。出厂预置且可编辑的声明归入普通配置；系统生成对象只有在已核实支持现有标准声明所需的独立生命周期操作时才可标为 `independent`，仍须检查具体操作及字段的支持范围。来源与管理能力分别判断，不能由其中一个直接推导另一个。

仅能覆盖部分设置，不足以证明可独立删除、重建或激活恢复。本轮不引入操作／字段权限矩阵：原生允许局部覆盖、但适配器不能可靠表达其操作边界的对象，将管理能力标为 `unknown`，附受控原因 `partial_management_unsupported`，默认保留可见并阻止独立操作。只有来源管理方式已核实时才使用 `via_source`，不能为隐藏对象而猜测该值；局部可编辑也不应被标为原生完全只读。

已核实原生类型／来源关联／生成规则优先，名称仅辅助。不能从 UUID、名称前缀、`external`、动态地址、空成员或转换失败推断只读；缺失、冲突和不支持版本按受影响维度报未知。分类不能清除转换失败或把异常标记降格成普通元数据后接受。

备选方案“按名称白名单过滤”无法防止误判用户对象；“单个 readonly 布尔值”无法表达来源配置管理及局部覆盖，均不采用。

### 2. 完整观察与展示投影分离

Reader 内部不按系统来源过滤。read 保存经现有脱敏规则处理的完整范围观察至私有 `diagnostics/observations.json`，用户读取结果采用单独生成的视图；计划、apply、verify、恢复继续直接取得完整观察，不能读取展示投影作为状态依据。

默认仅隐藏 `origin` 已确认为 `system_builtin` 或 `derived`，且 `management` 为 `via_source` 或 `read_only` 的对象详情。来源或管理能力未知、独立可管理、普通配置转换失败均保留。默认过滤不改变底层观察状态、错误和覆盖范围；隐藏对象中的读取或转换问题仍计入相应摘要。

运行选项 `include_system` 默认为 false，必须为严格布尔值，仅用于 read；本地 read 命令提供 `--include-system`，其他操作拒绝该展示选项。true 仅关闭系统项隐藏，仍遵守原资源／对象选择，不额外访问 PF 或其他资源。显式选择且可按现有身份契约定位的对象始终返回详情，避免把已存在的系统对象显示为不存在；不在此变更中扩展 native 身份选择语法。

结果区分底层枚举数量、选择匹配数量、展示数量和隐藏数量，标记是否进行了投影及其范围。分类计数按来源和管理能力各自统计，另报普通配置的表达成功／失败、未知项，不能把交叉维度相加当作对象总数。隐藏数等于选择匹配数减展示数，不伪造分页总量；不完整观察只能提供已观察数量并保留 incomplete。

不直接删除 Reader 对象：系统 Alias／组等仍可能是必要引用目标，也可能提供反向引用保护。展示投影不能证明完整性或对象缺失；通过单独视图标记和新结果版本与执行观察区分。

当前依赖校验还要求目标 `configuration` 非空并检查 Alias 类型，因此仅保留对象不足以支持系统引用。本轮明确包含：在固定支持版本能证明身份、引用角色和必要依赖边界时，允许用户规则引用不可表达的系统地址／端口 Alias 或系统接口组。观察为这些目标保留最小引用描述（稳定引用标签、支持的地址／端口／接口组角色、必要的地址族及安全依据），与 `classification`、标准 `configuration` 分开；不伪造用户声明。已有标准校验和必要的反向引用、传递依赖及循环检查仍然执行，缺少相应证据不能默认空依赖。

该支持仅用于已确认的系统内置／派生目标和已核实的消费者字段角色；普通用户配置转换失败、来源未知或原生响应畸形不能利用此路径绕过配置检查。地址角色不能充当端口角色，接口组不能冒充 Alias。证据不足时阻断相关引用，分类成功本身不代表引用兼容。最小引用描述纳入必要依赖观察和候选／执行的相关漂移检查，不扩大 Alias 内容解析、运行状态验证或完整资源声明范围。

### 3. 分类是管理能力检查，不是授权

对现存对象的独立变更、接管及激活恢复，要求有可靠的独立管理能力证据，再执行原有声明、显式选择、managed／adopt、漂移和激活检查。`via_source`、`read_only` 或管理能力未知时阻止独立操作，说明原因及已知来源位置；不静默跳过后报告成功。来源未知本身不产生权限；若独立管理能力能另行可靠证明，仍按普通授权链判定。

完整观察证实不存在的新对象，继续走现有支持资源的创建准入，无需为不存在对象编造来源。分类不扩大写入选择，未选中的未知／不支持对象不应无条件阻断无关操作；仅在必要依赖、反向引用或受影响状态无法确认时阻断。

候选保存与准入有关的分类和安全依据。apply 在原有必要状态重读边界检查管理能力及来源关联的相关变化：管理能力失去可靠支持、变为非独立管理或未知，或相关来源关联变化时须重新规划。若仅修正 `origin` 标签，独立管理能力、支持依据及相关来源关联均未变化，不因该标签单独阻断；相关引用角色或其支持证据变化仍按依赖漂移处理。展示开关不参与候选语义或影响漂移结果。无需逐对象新增 hash，复用现有候选摘要。

恢复仅对支持独立管理且前后态充分的对象生成反向候选。系统派生项通过显式选择且受支持的来源配置处理；不自动补选来源、不为观察到的系统项生成删除。可表达性与可恢复性不等价，现有 `manual_required` 不能因分类成功被升级。原本不存在的新建用户对象保留显式逆删除，仍检查当前管理能力、引用及漂移。

独立用户对象删除后的逆创建同样保留：恢复材料须记录删除前真实配置及管理能力证据、原执行与已确认删除后态；当前完整确认该身份仍不存在时，按既有支持创建和引用准入生成显式逆创建，不要求不存在对象提供 live classification。若身份已被新对象占用、当前观察不完整或重建范围缺证据则阻断，不把逆创建悄悄变成更新。新建或逆创建后的回读须确认实际管理能力，正常的 absent→independent 转换不视作外部漂移；缺失或不符仍保留失败／未知并停止后续变更。

### 4. 结果和执行材料明确迁移

计划将 candidate、result、recovery 从 v2 更新到 v3；request 保持 v1，展示选项走运行选项边界。保留标准声明、资源身份、`read_only` 的操作含义和既有确认结果语义。

v3 执行加载器拒绝旧候选及缺少必要分类的伪 v3 材料并给出重新读取／规划提示，不在 apply 中自动补分类。旧恢复材料保留原始证据，不能静默升级为自动恢复；需人工核对原执行与当前状态后准备新的显式方案。回滚运行版本时须同时使用该版本可接受的材料，不能混用或伪造格式版本。

完整观察产物仍为机器处理的规范输入形态；默认读取结果为带范围标记的展示视图，下游消费者必须显式区分。infra-ops 的适配另行承接，本 change 提供迁移说明而不修改兄弟仓库。

正式 runtime 和本地 local 入口均使用明确的 v3 结果版本及同义的完整观察／投影范围标记；本地模式可以保留自己的运行身份信息，但不能继续输出无法识别版本或视图语义的 read／plan／verify 结果。两个入口使用同一组代表性契约断言，避免只升级正式结果。

## Risks / Trade-offs

- 原生分类字段随版本变化 → 实现前核对固定支持版本；无可靠规则的对象保持未知，不为覆盖率猜测。
- 默认隐藏掩盖缺口 → 未知和普通配置失败默认展示，隐藏对象仍有分类及错误摘要。
- 过滤破坏引用检查 → 执行流程只用完整内部观察，验证开关对计划与依赖结果无影响。
- 新材料版本影响调用方 → 明确旧候选重新规划、旧恢复材料保留及人工处理边界，提供迁移示例。
- 本地模拟不能代表设备 → 仅以代表性离线夹具和现有工作流回归验收本阶段，不声称真机或业务验证。

## Migration Plan

用户审阅并授权实施后，先核实分类证据和适配规则，再实现分类、展示、管理准入及契约迁移；完成离线回归和使用文档。没有分类依据的资源按未知处理，不作为新增设备读取或写入窗口的隐含授权。发布、调用方部署及实机验收另行安排。
