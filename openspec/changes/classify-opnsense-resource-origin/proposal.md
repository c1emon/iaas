# OPNsense 资源来源分类与读取视图

## Why

当前 workflow 将系统内置、派生对象与不支持的用户配置一起输出为 `configuration=null`、`manual_required`，缺少来源与管理能力信息。调用方难以区分正常系统依赖和真实支持缺口，也不能仅凭配置可表达就确认对象可独立管理。

依据：`../infra-ops/docs/operations/opnsense-resource-origin-classification-handoff.md`。其中设备数量和对象示例是交接证据，不是通用分类规则。

## What Changes

- 对现有七类资源分别表达来源、管理能力、配置表达能力、必要的数据性质及安全分类依据；缺证据保留未知。
- 内部观察保留完整的已枚举对象及依赖；默认读取视图隐藏已确认不可独立管理的系统内置／派生对象详情，保留数量摘要。
- 对不可表达的系统 Alias／接口组，保留经核实的最小引用身份和角色，支持现有规则的兼容引用；不伪造标准配置或跳过类型与依赖检查。
- 增加 read 专用 `include_system` 布尔选项，本地命令对应 `--include-system`；开启后展示当前选择和枚举范围内的全部对象，不扩大读取能力或管理授权。
- 预置可编辑配置、来源未知项及用户配置转换失败项默认可见；显式读取具体系统对象时返回其详情和限制。
- 计划、执行及恢复按独立管理能力准入，保留依赖检查、漂移检查、所有权及现有激活确认边界。
- 局部设置可覆盖不等于完整生命周期可管理；本轮无法表达操作边界的对象保持可见并阻断独立操作，不新增权限矩阵。
- **BREAKING**：更新结果、候选与恢复契约版本，区分过滤视图和完整观察；旧执行候选不得隐式升级，需重新规划。旧恢复材料保留，但不能直接获得新的自动恢复准入。

## Capabilities

### Modified Capabilities

- `opnsense-config-workflow`: 增加资源分类、默认读取视图、系统项展开、分类准入及兼容性要求；修订转换输出契约。

## Non-goals

不新增资源种类，不扩展完整 PF 活动规则枚举，不提升 Gateway 等资源的配置表达范围；不访问设备、不开展实机写入、业务验收、发布或 infra-ops 实现。不引入分类插件框架、逐对象证据系统或穷举版本矩阵。

当前授权仅为建立本 change 并校验，等待用户审阅后另行开始实现。

## Impact

后续涉及 workflow reader／conversion、contracts、planning、executor、runtime／local 入口、相应运行选项校验、文档和代表性离线测试。标准资源声明及站点所有权仍由现有契约和调用方负责。已有结果消费者需适配视图计数与新版本，不能把过滤结果当作完整资源集合。
